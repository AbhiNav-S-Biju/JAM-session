# Front-end handoff

For whoever takes over the UI. You can do all of this without touching the engine.

## What exists

| Page | File | Data it draws | How to open |
|---|---|---|---|
| Launcher | `real/index.html` | none (links only) | double-click |
| 2D demo (simulated home) | `demo/index.html` | `demo/results.js` | double-click |
| 2D real map | `real/out/map.html` | inlined at generation | double-click |
| 3D sim (simulated or real) | `iot/index.html` (`?data=real` for your network) | `demo/results.js` or `real/out/results.js` | double-click |
| Static before/after report | `out/before_after.html` | generated by `src/report.py` | double-click |

Every page works from a double-click: no server, no internet. Data arrives through a `<script>` tag that sets `window.RESULTS`, because browsers block `fetch()` of local files. `iot/vendor/` holds three.js so the 3D page works offline.

## Generate the data first

```
python -m venv .venv && .venv\Scripts\activate && pip install -r requirements.txt
python -m src.main scenarios/home.yaml --out out/        # writes demo/results.js (simulated home)
python -m real.main --input real/tests/fixtures --out real/out_test   # fake "real" data, safe to share
```
Your own network (needs the owner's confirmation flag, see `real/README.md`):
`python -m real.main --quick --subnet 192.168.0.0/24 --i-own-this-network`

## The data contract: `window.RESULTS`

Documented at the top of `src/report.py`. The fields the pages use:

```
foothold            id of the compromised device
thresholds          {outbound_mb_limit, beacon_min_count, beacon_window_s}
policies[]          {id, description}, in strictness order: first = open, last = default-deny
before_policy / after_policy
zones[]             {name, x, y, w, h}          2D map coordinates
devices[]           {id, name, zone, type, critical, x, y}
hosts[]             {id, name, known, x, y}     outside destinations; known=false = unlisted
cases[]             {id, name, flows[{src,dst,bytes,t}],
                     results{ <policy id>: {blast_radius, total, reachable[], reach_edges[[parent,child]],
                                            laptop_outbound_mb, delivered[bool per flow], alerts[{kind,message,...}]} },
                     checks[]}
```
Rules for your code:
- **Draw only what is in `RESULTS`.** No hardcoded device names, numbers, policy names or positions. Policy order tells you "how strict" (the 3D page derives wall colour from the policy's position in `policies[]`).
- `reach_edges` is a shortest-path tree in BFS order (parent before child). Hop depth = parent's depth + 1. The 3D page animates one hop per step from this.
- Names can contain odd characters. Use `textContent`, never `innerHTML`, for anything from `RESULTS`.
- A page must show a helpful message, not a blank screen, if `RESULTS` is missing. The existing pages show the command to run.

## Polish list (suggested, in priority order)

1. **Keep keyboard focus after a click** in the 3D side panel. It rebuilds the panel on every click, so focus jumps back to the page. Restore focus to the pressed chip.
2. **Mobile layout of the 3D page**: check at 390 px wide; the canvas is 58 vh, the panel scrolls below.
3. **One look across pages.** The 2D pages follow light/dark; the 3D page is dark only. Pick one set of colour tokens and share them.
4. **Colour-blind check**: orange (reachable) vs red (compromised) and green (contained) vs amber (limited). Add a shape or text cue where colour is the only signal.
5. **Label legibility in 3D** when zoomed out; consider hiding device labels beyond a distance.
6. **Real-network naming**: the real map shows `unknown-xx-xx-xx` until `names.csv` is filled in. A small "how to name devices" hint on the page would help.
7. **Reduced motion**: already respected (animation skipped). Keep it that way for anything you add.

## Constraints

- Offline: no CDN links. Any library goes under `iot/vendor/` (or similar) with its licence and a version note.
- No data leaves the machine. No analytics, no remote fonts or images.
- MAC addresses must never appear on a page (the engine masks them in files; the pages do not show them).
- Keep it honest: the real pages say "REAL NETWORK", simulated pages say "SIMULATED", cases that replay pretend attacks are labelled `[SIMULATED]`, and the phase-2 hub is labelled "concept".

## Check your work

```
python -m pytest -q            # the engine and real/ tests must still pass
```
Then open each page, switch every scenario and policy, and confirm the numbers match `out/report.md` (for the simulated home: camera case 7 of 7, 2 of 7, 1 of 7 under `flat`, `vlan_only`, `vlan_deny`).
